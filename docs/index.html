    How to lay out the CSV
    
  
    One row per employee, per labor class, per day worked. The first row holds the column names below. Column order does not matter. Excel's "CSV UTF-8" save works best.
    
  
    Excel rewrites some cells when it saves. Dates like 2026-10-04 come back as 10/4/2026, and this tool reads both. A project number that looks like a date can turn into a date, so format that column as Text before you save.
    
  
    
    
    
  
    
  
    
    
    
      
    ColumnWhat goes in it
    
      
        
    vendor_idYour vendor ID with the state. Same on every row.
    
        
    contract_idThe contract number, no dashes or spaces. Same on every row.
    
        
    payroll_numberThis week's payroll number, a whole number starting at 1. Same on every row.
    
        
    period_begin, period_endFirst and last day of the pay week, as 2026-10-04 or 10/4/2026. Seven days. Same on every row.
    
        
    fringe_typeFringe benefit payment type from your state's list. The sample uses Cash.
    
        
    last_name, first_nameThe worker's name.
    
        
    middle_initialOne letter, or blank.
    
        
    ssnAll 9 digits, or the last 4. Dashes are taken out for you.
    
        
    employee_idYour own ID for the worker. Can be blank.
    
        
    genderMale or Female. M and F work too.
    
        
    ethnicityThe code from your state's list.
    
        
    craft_code, labor_classCodes from your state's list.
    
        
    project_idThe project number on the contract.
    
        
    apprenticeY or N.
    
        
    st_rate, ot_rateStraight time and overtime hourly rates.
    
        
    work_dateThe day worked, as 2026-10-05 or 10/5/2026.
    
        
    st_hours, ot_hoursHours that day. A blank counts as 0.
    
        
    gross_pay, total_deductions, net_pay, fica, federal_tax, state_tax, medicareThe week's totals for this worker and labor class. Repeat them on each of that worker's day rows. If they differ between rows, the tool stops and names the row.
    
        
    other_deductionsPairs like Union dues:38.37, split by semicolons. Blank if none.
    
          
    
    
  
    
  
    The sample uses Wisconsin's codes as they appear on the WisDOT spreadsheet template. Your state's codes may differ. This tool passes codes through as you typed them. It cannot tell you if a code is wrong.
    

  
    What the check looks for
    
  
    Each rule is something a state import rejects, taken from state import pages and the official field definitions.
    
  
      
    
    • The pay period is seven days, and every day worked falls inside it.
      • 
    
    • The payroll number is a whole number starting at 1.
      • 
    
    • The contract ID has no dashes or spaces.
      • 
    
    • Every day has straight time and overtime filled in, 0.00 when there were none.
      • 
    
    • Daily hours add up to the straight time, overtime and total hours for the week.
      • 
    
    • Gross pay minus deductions equals net pay.
      • 
    
    • Gender, when filled in, is the word Male or Female.
      • 
    
    • A full SSN is 9 digits with no dashes. A middle initial is one character.
      • 
    
    • Every employee has a change indicator.
      • 
    
    • No field runs past its length limit.
      • 
  
    

  
    What it does not check
    
  
    The full Payroll XML schema. That check needs AASHTO's schema files, which this page does not carry. Run your file through the official online validator before you upload, or use the Python version of this tool, which checks the schema and the rules together.
